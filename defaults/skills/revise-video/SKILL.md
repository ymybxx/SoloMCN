# 修改视频

参数里有 `内容 id` 和 `修改意见`。你是在工作台后台被调起的，**没有人能回答问题**：意见有歧义时，选最合理的理解去改，并在登记的 `notes` 里写明你是怎么理解的。

可用的：`workbench` MCP 的 `get_item`、`save_video`；命令行、读写文件、技能、子代理。没有网页搜索。

## 1. 找到项目和要改的地方

1. 调用 `get_item`。`item.video` 是空的就说明并停下。`item.video.project` 是 HyperFrames 项目目录（相对当前工作目录），`item.video.mp4` 是当前版本。
2. 读项目的 `BRIEF.md`、`STORYBOARD.md`，了解这条视频。
3. **意见里附了图**（提示里会列出"图 1：<路径>"）：先用读文件工具逐张查看。通常是成片当前画面的截图（意见里写着"[61.2 秒] 见图 1"，说明这张就是那个时间点的画面），也可能是用户想要的参考样式。按图理解意见，图和文字冲突时以文字为准。
4. 意见里带了时间点（例如 `[61.2 秒]`）：运行 `npx hyperframes timeline --json` 找到那个时间点所在的分镜和元素。时间点指的是**当前版本的成片**。没带时间点：按描述的内容（文字、画面）在 `compositions/frames/` 和 `index.html` 里找。
5. 改之前先截一张图看清现状：`npx hyperframes snapshot --at <时间点>`。

## 2. 只改提到的地方

这是对已有项目的**定点修改**，按 `/hyperframes` 的"对现有项目的具体修改"处理：直接改，不跑完整的生成流程，不重新规划分镜。

- 改动前读 `/hyperframes-core`，涉及动画读 `/hyperframes-animation`，涉及声音读 `/hyperframes-audio`
- 只动和意见有关的文件和元素，其他分镜、配音、音乐保持原样
- 意见要求补真实画面（价格、规则、产品页、帖子、演示视频）时，按 `/make-video` 的「真实素材：截图和视频片段」做：先用 `get_item` 的 `assets`，不够就用 `npx hyperframes capture` 截公开网页或取页面视频，网址和日期记后台 notes，不加成画面脚注
- 意见要求改台词或配音时，只重新合成受影响的那几句，并同步时长和字幕。配音按 `/voice-over` 技能做，用和原片相同的方式和音色（看项目里的 `audio_meta.json` 或备注）；意见是「听不懂」「配音不自然」之类的，按 `/voice-over` 里的顺序换一种方式整段重配，再重新对齐字幕
- 生成阶段不添加 AI 标识、虚构/示意/非实测说明、安全提示或免责声明，统一留给用户在成片阶段处理。修改前清理旧脚本和项目中会进入画面、配音、字幕的附加提示，不用解释性台词替代被删除的角标。
- 本规则和最新修改意见优先于旧脚本、调研建议、卡片备注、历史视频说明、BRIEF、STORYBOARD、frame.md 的标注要求。同步相关约束和自动注入脚本，避免重新组装或渲染后又被加回去。
- 素材不足时删去无依据的断言或换成有依据的镜头，来源和问题只记后台 notes，不用“无可靠数据”等画面提示占位。
- 意见要求伪造的（编造数据、测试结果，或用 AI 合成真人的脸、声音让他说没说过的话），不照做，在 notes 里说明原因，其余照常改

## 3. 检查和渲染新版本

1. 改完运行 `npx hyperframes lint` 和 `npx hyperframes check`，再对改过的时间点截图确认效果。
2. 渲染成**新文件**，不要覆盖旧版本：看 `renders/` 里已有哪些，取下一个版本号，例如 `npx hyperframes render --quality high --output renders/video-v2.mp4`。
3. 等待耗时命令时直接在前台运行，不要用 `sleep` 空等。收尾前确认自己放到后台的命令都已经结束，不再需要的直接停掉，否则这次运行会一直挂着显示「修改中」。

## 4. 登记

调用 `save_video`：`item_id`、新的 `mp4`、`project`、`contact_sheet`（有新截图就填）、`duration_s`、`notes`。notes 写：
- 你理解的修改意见
- 具体改了什么（哪个分镜、哪个元素、改前改后）
- 没改的部分和原因（如果有）

## 5. 汇报

两三行：改了什么、新版本路径和时长、需要人再看一眼的地方。
