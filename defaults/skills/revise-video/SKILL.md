# 修改视频

参数里有 `内容 id` 和 `修改意见`，可能还带 `做法：<技能名>`。你是在工作台后台被调起的，**没有人能回答问题**：意见有歧义时，选最合理的理解去改，并在登记的 `notes` 里写明你是怎么理解的。

可用的：`workbench` MCP 的 `get_item`、`save_video`；命令行、读写文件、上网、技能、子代理；你配过的钥匙和登录在环境变量里。

## 1. 读取内容和意见

1. 调用 `get_item`。`item.video` 是空的就说明并停下。`item.video.project` 是项目目录（相对当前工作目录），`item.video.mp4` 是当前版本。
2. **意见里附了图**（提示里会列出"图 1：<路径>"）：先用读文件工具逐张查看。通常是成片当前画面的截图（意见里写着"[61.2 秒] 见图 1"，说明这张就是那个时间点的画面），也可能是用户想要的参考样式。按图理解意见，图和文字冲突时以文字为准。

## 2. 按做法改

用哪种做法：参数里的 `做法：`，或者 `get_item` 的 `craft`；都没有就看项目目录，有 `montage.json` 的是 `stage-montage`，其余是 `explainer-video`。读那个做法技能目录里的 `revise.md`，照它改。

不管哪种做法都适用的：

- **只改意见提到的地方**，其他保持原样；为了让改动成立必须跟着动的才一起动。
- **只重做受影响的那一段**：时长不变的小改（换一句配音、改一条字幕、改一个镜头），不要整条重新渲染，做法的 `revise.md` 里写了怎么局部重做再拼回去。
- **输出新文件**，不覆盖旧版本（`renders/video-v<N>.mp4`）。
- 生成阶段不添加 AI 标识、虚构/示意/非实测说明、安全提示或免责声明，统一留给用户在成片阶段处理。修改前清理旧脚本和项目中会进入画面、配音、字幕的附加提示，不用解释性台词替代被删除的角标。
- 本规则和最新修改意见优先于旧脚本、调研建议、卡片备注、历史视频说明、BRIEF、STORYBOARD、frame.md 的标注要求。同步相关约束和自动注入脚本，避免重新组装或渲染后又被加回去。
- 素材不足时删去无依据的断言或换成有依据的镜头，来源和问题只记后台 notes，不用“无可靠数据”等画面提示占位。
- 意见要求伪造的（编造数据、测试结果，或用 AI 合成真人的脸、声音让他说没说过的话），不照做，在 notes 里说明原因，其余照常改。
- 等待耗时命令时直接在前台运行，不要用 `sleep` 空等。收尾前确认自己放到后台的命令都已经结束，不再需要的直接停掉，否则这次运行会一直挂着显示「修改中」。

## 3. 登记

调用 `save_video`：`item_id`、新的 `mp4`、`project`、`contact_sheet`（有新截图就填）、`duration_s`、`notes`。notes 写：
- 你理解的修改意见
- 具体改了什么（哪个镜头、哪一刀、改前改后），是局部重做还是整条渲染
- 没改的部分和原因（如果有）

## 4. 汇报

两三行：改了什么、新版本路径和时长、需要人再看一眼的地方。
