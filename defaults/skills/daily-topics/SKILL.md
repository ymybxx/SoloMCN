# 每日选题

目标：每天为每个正在运营的账号产出几条**能借势、贴人设、不伪造**的短视频选题，写进工作台的「账号选题」，由人来挑。

工具来自项目的 `workbench` MCP 服务。如果工具报“连不上工作台服务”，告诉用户在项目目录运行 `npm start`，然后停下，不要改用别的方式写数据。

## 参数

用户没说就用默认值：

- 每个账号 **3 条**选题
- 只给**正在运营**的账号出题
- 用户点名某个账号、某个平台或某个方向时，照用户说的来

## 流程

### 1. 摸清现状

并行调用：

- `get_accounts`：账号人设和系列，系列里的 `topics` 是这个系列适合的题材（没建系列的老账号看人设），选题必须贴合
- `get_recent_context`：雷达里还没处理的选题和最近的内容，**不要出重复或高度相似的题**；看 `topPerformers`，表现好的情绪和形式可以多用

### 2. 看热点

调用 `get_hot_topics`（默认 40 条）。重点关注：

- `fresh`（3 小时内新上榜）和 `rising`（一小时内排名大幅上升）：时效最好，优先考虑
- `on` 里平台多的：全网都在聊，受众最广
- `hotVideos`：B站热门视频在做什么题材和形式，借鉴形式而不是照搬内容
- 带 `caution` 的：可以做，但要格外小心处理

再调用 `get_overseas_hot` 看 Hacker News 首页和推特趋势榜（推特号池里有账号才有），推特号池有账号时再用 `get_feed`（`channels: ["x"]`）看推特最近 24 小时涨得最快的帖子：海外刚火、国内还没人做的新产品、新工具、新玩法，是信息差素材。

然后用网页搜索补两类信息：

1. **小红书和抖音的生活方式趋势**：热榜覆盖不到的“情绪类、生活类”话题，比如节日节点、季节情绪、流行梗、打工人话题。搜一两次即可，例如“本周 小红书 热门话题”“最近 抖音 流行梗”。
2. **看不懂的热点**：标题信息不够时，搜一下来龙去脉再决定能不能做。不要凭标题猜事件。

### 3. 筛选：哪些热点能做

一个热点要同时满足三条才进入下一步：

1. **能按账号风格形成有价值的内容**。可以做有依据的解说、演示或剧情，不强制把真实素材改成虚构道具；后台审阅备注不要变成台词或画面提示。
2. **至少一个账号的人群会关心、在它的选题范围里**：对照人设和系列 `topics`，看是不是它的题材、按它的做法能不能做出来（做法要用的素材找不找得到）。
3. **不碰红线**（见下文）。

直接跳过和所有账号的选题范围都对不上、硬凑也做不出来的热点。平台审核可能敏感的题材（时政、灾难、争议议题）不替人跳过，写进 `risk` 让人决定。

### 4. 转化：热点 → 账号选题

**先定系列。** 账号有系列（`get_accounts` 的 `series`）时，每条选题先决定归到哪个系列，再按那个系列的定位、固定结构和适合的题材来设计；同一个主题可以给同一账号的不同系列各出一条，角度要按系列的做法变。写入时 `series` 填系列名。

对每个选中的热点，问“这个账号的人群在这件事上有什么情绪”，再按系列的做法放大。手法按账号的做法挑，下面是常用的几种，不是每个账号都适用：

| 手法 | 例子 |
|---|---|
| **角色代入**：让账号固定的角色经历这件事 | 返程高峰 → 打工动物堵在高速上开视频会 |
| **荒诞放大**：把热点情绪推到极致 | “来不及写作业” → 古代书童连夜帮皇帝补奏折 |
| **时空反差**：放到古代、未来或动物世界 | 国庆返程 → 1990 年的绿皮火车春运 |
| **情绪共鸣**：只取情绪，不提事件 | “下次回来就是 2027 年了” → 离家时爸妈站在路口的背影 |

每条选题按人性的几个按钮检查：

- **前 3 秒**：`hook` 的第一句台词先说出主题，再接违和感或好奇缺口。标准按 write-script 第 4 步的开头检查：看完第一句能复述出「这条讲的是 XX」，只有场景、道具不算；不合格就改写 `hook`
- 命中哪种**高唤醒情绪**：感动、好笑、震惊、爽感、怀旧、治愈
- 目标人群会不会觉得**“说的就是我”**
- 转发出去，转发的人**显得怎么样**（有趣、有共鸣、有品位）

### 5. 打分

四项各 1–5 分，**如实打**，大部分应该在 2–4 分：

- `hook`：前 3 秒的抓人程度
- `emotion`：情绪强度
- `relate`：目标人群的代入感
- `social`：转发欲望

总分低于 11 分的题不要写进雷达。每个账号凑不够数，宁可少出也不凑数，并说明原因。

### 6. 写入

调用 `add_ideas` 一次性写入。每条都要：

- `account` 用账号代号
- 借势热点的，填上 `trend`（原标题和平台排名）和 `whyNow`
- `series` 填归到的系列名（账号有系列时必填）
- `risk` 只写事实层面要核实的地方和平台审核可能敏感的地方，一两句话，供人参考；不写“不点名”“不展示截图”这类创作限制。确实没有就写空字符串

### 7. 汇报

用几行话告诉用户：

- 今天热榜的整体情况：大家在聊什么，有哪些热点被你跳过了以及原因
- 每个账号出了几条，最推荐哪一条、为什么
- 提醒用户去工作台的「账号选题」挑选

不要把全部选题在聊天里重复一遍，工作台里都有。

## 红线

**唯一的红线：不伪造。** 不编造新闻、事件、测试结果和数据；不合成真人的脸或声音，让他说没说过的话、做没做过的事。除此之外不设限制：可以点名真实的公司、产品、开源项目、博主和公众人物，可以用他们公开的网页、帖子截图和官方视频片段做介绍和评论（出处记在后台）。

另外：矩阵里不同账号的选题角度必须真的不同，不是一个题换个皮（平台会把同质内容判成批量生产）。
