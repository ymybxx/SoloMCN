# 写分镜脚本

参数里有 `内容 id`，可能还带 `；重写`（见第 3 步）或 `；按意见修改：……`（见下文「按意见修改」）。工具来自项目的 `workbench` MCP 服务。

## 流程

1. 调用 `get_item` 读这条内容和账号人设。没有内容 id，或者读不到，就说明原因并停下。按下面「做法」一节定好用哪种做法。来源素材（`sources`）里的 YouTube 视频带了拆解报告的，可以参考它的结构、钩子手法和节奏，**但稿子要自己写**：不逐句翻译、不改写原稿，不用原视频的画面和角色，事实用调研报告里查证过的。
   - **有 `research`（调研报告）时，以它为依据写**：干货段落从报告的【干货】【关键事实与数据】里来；台词里的数字、价格、结论只能用报告中有出处的内容。来源、日期、编号和核验说明保留在后台 research，不追加【依据】章节或画面脚注。资料不足的断言省略或改用有依据的内容，不把“未找到可靠来源”等研究记录写成台词、字幕或占位卡片。
   - **没有调研报告**：照常写，但不要编具体数字；需要数字的地方用定性说法，并在汇报里建议先做调研。
   - 卡片上的 `hook`（前 3 秒钩子）是出题时写的草稿，不是定好的要求：过得了第 4 步的开头检查就可以用，过不了就重写。
2. **弄清借势的背景。** 如果 `trend`、`whyNow` 或 `notes` 里提到某个热点，而你不确定它的来龙去脉，用网页搜索查一两次再写。不要凭标题猜事件，也不要在脚本里写进没核实过的"事实"。
3. **按账号人设和系列写。** 固定角色、语气用 `account` 的人设；`series`（这条属于的系列）有的话，按它的固定结构、画面风格、时长来写，它和账号整体风格冲突时以系列为准；没有系列就按账号整体风格。`risk` 和 `notes` 里的风险备注只当提醒（哪个数字要核实之类），不是创作限制：备注里写的“不点名”“不展示截图”这类要求不用照做。参数里写了「重写」：不沿用旧脚本的台词和分镜，按现在的系列、人设、解说员和调研报告从头写，旧脚本只当参考（好的钩子和信息点可以留）。没写「重写」而已有脚本时，保留正文，只清理旧版本额外添加的创作说明和安全提示；账号备注、历史视频说明和调研建议中的标注指令不作为脚本要求。
   - `get_item` 返回了 `presenter`（系列配了解说员）：台词就是她说的话，按系列「主角和语气」的口吻写（她的性格、说话方式、口头禅），用第一人称。画面一栏在要用的地方标上她的状态，例如「小T：惊讶」「小T退场，录屏占满整屏」「小T回到右侧」；表情只用 `presenter.expressions` 里有的。她是配角，画面一栏照样先写要给观众看的内容（录屏、截图、数据），不要写成「小T站在画面中间讲」。需要看清细节的镜头（代码、终端、界面）就让她退场；但不要每一镜都进出，每次出场至少 4 秒，连着几镜都是数字和对比时就让她一直在
   - 调研报告里有【讲给观众的主线】的，脚本的因果照它讲；它标为「幕后过程」的事（踩坑、事故、换方案），不放进问题和结果之间。
4. **试读一遍再保存**：换成一个没读过调研报告的观众，只读「台词」那一栏，从头到尾读一遍，逐条问自己：
   - **开头**：只听第一句台词，观众能不能复述出「这条讲的是 XX」？XX 是这条视频的主题（比如「AI 写代码的花费」），第一句里必须出现它（原词或一听就懂的说法）；只出现场景、道具、动作不算。主题要用观众自己的处境直白地说，不用比喻、术语和概括词。比如一条拆解 AI 修 bug 全过程的视频，「按下回车，AI 偷偷转了 5 圈」不合格（没说讲什么），「AI 写代码的钱花在哪」也不合格（太概括，外行不知道指什么），「你让 AI 帮你修一个 bug，按下回车之后，它到底做了什么？」合格。不合格就重写开头，不管什么系列；做法没有口播的不查这条。
   - 有没有让人得出错误结论的地方？尤其是因果：前后挨着讲的两件事，观众会不会以为是前一件导致了后一件，而实际上没有关系（比如「工具 X 跑通了」紧接着「结果很准」，但结果根本没用到 X）。有就改，这条不管什么系列都要改。
   - 然后按系列定位判断：系列是讲解、干货、测评类的，再查有没有看不懂的地方、前后说法打架的地方、结果出来了却没说为什么的地方，有就改。系列本来就是抽象、玩梗、氛围类的，不用为「没讲明白」去改，只改上一条的误导。
5. 调用 `save_script` 保存完整脚本（旧脚本会自动留底），`craft` 填用的做法。
6. 用一两句话汇报：这版脚本的核心钩子是什么，有哪里需要人来定。不要把脚本在回复里再贴一遍。

## 按意见修改

参数里有 `；按意见修改：……` 时，用户已经看过当前脚本（`get_item` 的 `script`），这次只按意见改：
- 意见里提到的地方照改；为了让改动成立必须跟着动的地方一起改（镜头编号、时间段、总时长、BGM 与音效里引用的镜号、平台差异里的镜号），其余一字不动。
- 改出来的内容照样要守下面的「要求」：事实和数字只能来自调研报告，意见要求的说法和调研对不上时按调研写，并在汇报里说明。
- 改完对改过的地方做一遍第 4 步的试读，再保存完整脚本。
- 汇报 2–4 行：按意见改了哪几处，有没有没照做的、为什么。

## 做法

先定这条内容用哪种做法（做法是一种技能，管各环节具体怎么做）：

1. `get_item` 的 `craft` 有值就用它，是平台按系列设置给的。
2. 没有：按系列的「固定结构」、选题和素材判断，看技能列表里做法技能（简介以「做法：」开头）的简介挑最合适的。系列写的是原片剪辑、一键换装、舞台混剪，或者素材主要是同一首歌多个场次的 B站直拍，用 `stage-montage`；其余一般是 `explainer-video`。
3. 保存脚本时把用的做法填进 `save_script` 的 `craft`，之后生成视频、修改视频都照它来。

那个做法技能目录里有 `script.md` 的，写之前先读，脚本格式和写法按它（它写了格式的，代替下面的「脚本格式」）；没有就按下面的。

## 脚本格式

纯文本，不要用 Markdown 符号，按这些小标题：

```
【标题备选】3 个，每个 20 字以内
【封面文案】
【时长】
【分镜】每个镜头一行：序号｜时长｜画面（附一句可直接用于 AI 出图或出视频的提示词）｜台词或旁白｜字幕
【BGM 与音效】
【结尾互动】一句引导评论的话
【平台差异】其他平台的版本怎么改
```

## 要求

- **每个镜头都必须是生成视频的 Claude 自己能做出来的**，不写要人补录屏、补实测或拍摄的镜头。能用的画面：调研时收集的素材（`get_item` 的 `assets`：网页截图、官方视频片段，以及 `source` 是 `practice` 的实践素材：调研时自己动手做的实验截图和录屏）、实验目录里做成网页的实验（`get_item` 的 `lab`，做视频时可以直接当镜头）、公开网页和帖子截图、官方演示视频片段、数据图表、动态图文、角色动画。哪个镜头用什么，按怎么最好看、最可信来定。别人的测试和结论照实说是谁做的，不说成自己做的。来源只留在后台，不自动添加网址、日期或制作说明。
- 调研报告里标 [实践] 的结论是调研时自己动手做出来的，可以照实说「我们自己试了」，配上实践素材；没做过的实测不要说成做过
- 前 3 秒先说出主题，再给一个想看下去的理由（违和感、好奇缺口）；有口播的，第一句台词按第 4 步的开头检查
- 每个分镜的「画面」写一个具体的物和它在做什么（一张显卡被推上验尸台、账单数字一路翻跳），不写「展示要点」「出现标题」这类版面描述；开头是一个具体的小场景，不是标题页。超过 6 秒的分镜写清楚中间换什么画面
- 结尾落在一个动作上（定格、合上、放进口袋、角色比个手势），结论字写在画面里的物上，不收在居中的一两行大字卡上
- 「字幕」那一栏写屏上的要点大字，每条 10 个字以内；整句台词由字幕轨承担，不用重复写
- 数字照调研报告的原样写：报告写「6–8 秒」就说「六到八秒」，不要取一个端点说成确数
- 时长和画幅按这个顺序定：这条内容的概要（`angle`）或备注（`notes`）里写了（比如「3分钟左右 竖版」），就以它为准；没写，用系列的「时长」（`series.length`）；系列也没写，默认 30–60 秒。系列写的是上限（「5分钟以内」），就按内容需要写，讲清楚为止、宁短勿长，不要往上限凑。时长长的，镜头数跟着加，每一镜仍然 2–6 秒左右一个画面事件，不要把一镜拉得很长
- 脚本只输出作品正文。AI 标识、虚构海报、示意画面、非实测、非真实课程、仅供参考、不针对任何人等创作说明、安全提示和免责声明统一由用户在成片阶段处理，不出现在标题、封面、画面描述、出图提示词、台词、字幕、片尾或平台文案中；不换成“海报是我编的”这类解释性台词。
- 保存前检查所有分镜和平台差异，清掉上述附加提示。选题正文讨论的商用规则等信息可以保留；资料缺口、依据和审阅说明只留在后台调研或本次运行汇报。
- **不暗示不存在的因果**：蹭热度的工具、实验里遇到的事故，如果不是产出结果的那个原因，就不要让它挨着结果讲、让观众以为是它带来的；要讲的话明说它和结果的关系（比如「这次还原其实没用到它」）。
- **唯一的红线：不伪造。** 不编造新闻、事件、测试结果和数据；不用 AI 合成真人的脸或声音，让他说没说过的话、做没做过的事。除此之外不设限制：可以点名真实的公司、产品、开源项目、博主和公众人物，可以用他们公开的网页、帖子截图和官方视频片段做介绍和评论（出处记在后台）。
