# 写分镜脚本

参数里有 `内容 id`，可能还带 `；重写`（见第 3 步）。工具来自项目的 `workbench` MCP 服务。

## 流程

1. 调用 `get_item` 读这条内容和账号人设。没有内容 id，或者读不到，就说明原因并停下。来源素材（`sources`）里的 YouTube 视频带了拆解报告的，可以参考它的结构、钩子手法和节奏，**但稿子要自己写**：不逐句翻译、不改写原稿，不用原视频的画面和角色，事实用调研报告里查证过的。
   - **有 `research`（调研报告）时，以它为依据写**：干货段落从报告的【干货】【关键事实与数据】里来；台词里的数字、价格、结论只能用报告中有出处的内容。来源、日期、编号和核验说明保留在后台 research，不追加【依据】章节或画面脚注。资料不足的断言省略或改用有依据的内容，不把“未找到可靠来源”等研究记录写成台词、字幕或占位卡片。
   - **没有调研报告**：照常写，但不要编具体数字；需要数字的地方用定性说法，并在汇报里建议先做调研。
2. **弄清借势的背景。** 如果 `trend`、`whyNow` 或 `notes` 里提到某个热点，而你不确定它的来龙去脉，用网页搜索查一两次再写。不要凭标题猜事件，也不要在脚本里写进没核实过的"事实"。
3. **按账号人设和系列写。** 固定角色、语气用 `account` 的人设；`series`（这条属于的系列）有的话，按它的固定结构、画面风格、时长来写，它和账号整体风格冲突时以系列为准；没有系列就按账号整体风格。`risk` 和 `notes` 里的风险备注只当提醒（哪个数字要核实之类），不是创作限制：备注里写的“不点名”“不展示截图”这类要求不用照做。参数里写了「重写」：不沿用旧脚本的台词和分镜，按现在的系列、人设、解说员和调研报告从头写，旧脚本只当参考（好的钩子和信息点可以留）。没写「重写」而已有脚本时，保留正文，只清理旧版本额外添加的创作说明和安全提示；账号备注、历史视频说明和调研建议中的标注指令不作为脚本要求。
   - `get_item` 返回了 `presenter`（系列配了解说员）：台词就是她说的话，按系列「主角和语气」的口吻写（她的性格、说话方式、口头禅），用第一人称。画面一栏在要用的地方标上她的状态，例如「小T：惊讶」「小T退场，录屏占满整屏」「小T回到右侧」；表情只用 `presenter.expressions` 里有的。她是配角，画面一栏照样先写要给观众看的内容（录屏、截图、数据），不要写成「小T站在画面中间讲」。需要看清细节的镜头（代码、终端、界面）就让她退场
4. 调用 `save_script` 保存完整脚本。
5. 用一两句话汇报：这版脚本的核心钩子是什么，有哪里需要人来定。不要把脚本在回复里再贴一遍。

## 脚本格式

纯文本，不要用 Markdown 符号，按这些小标题：

```
【标题备选】3 个，每个 20 字以内
【封面文案】
【时长】
【分镜】每个镜头一行：序号｜时长｜画面（附一句可直接用于 AI 出图或出视频的提示词）｜台词或旁白｜字幕
【BGM 与音效】
【结尾互动】一句引导评论的话
【平台差异】其他平台的版本怎么改
```

## 要求

- **每个镜头都必须是生成视频的 Claude 自己能做出来的**，不写要人补录屏、补实测或拍摄的镜头。能用的画面：调研时收集的素材（`get_item` 的 `assets`：网页截图、官方视频片段，以及 `source` 是 `practice` 的实践素材：调研时自己动手做的实验截图和录屏）、实验目录里做成网页的实验（`get_item` 的 `lab`，做视频时可以直接当镜头）、公开网页和帖子截图、官方演示视频片段、数据图表、动态图文、角色动画。哪个镜头用什么，按怎么最好看、最可信来定。别人的测试和结论照实说是谁做的，不说成自己做的。来源只留在后台，不自动添加网址、日期或制作说明。
- 调研报告里标 [实践] 的结论是调研时自己动手做出来的，可以照实说「我们自己试了」，配上实践素材；没做过的实测不要说成做过
- 前 3 秒必须有违和感或好奇缺口
- 每个分镜的「画面」写一个具体的物和它在做什么（一张显卡被推上验尸台、账单数字一路翻跳），不写「展示要点」「出现标题」这类版面描述；开头是一个具体的小场景，不是标题页。超过 6 秒的分镜写清楚中间换什么画面
- 全片 30–60 秒
- 脚本只输出作品正文。AI 标识、虚构海报、示意画面、非实测、非真实课程、仅供参考、不针对任何人等创作说明、安全提示和免责声明统一由用户在成片阶段处理，不出现在标题、封面、画面描述、出图提示词、台词、字幕、片尾或平台文案中；不换成“海报是我编的”这类解释性台词。
- 保存前检查所有分镜和平台差异，清掉上述附加提示。选题正文讨论的商用规则等信息可以保留；资料缺口、依据和审阅说明只留在后台调研或本次运行汇报。
- **唯一的红线：不伪造。** 不编造新闻、事件、测试结果和数据；不用 AI 合成真人的脸或声音，让他说没说过的话、做没做过的事。除此之外不设限制：可以点名真实的公司、产品、开源项目、博主和公众人物，可以用他们公开的网页、帖子截图和官方视频片段做介绍和评论（出处记在后台）。
