# 拆解视频

参数在调用时给出，格式是：`视频 id：<11 位 id>`，后面可能带 `；重新拆解`。缺参数就停下说明，不要猜。

工具来自项目的 `workbench` MCP 服务。如果工具报“连不上工作台服务”，直接停下并说明原因。

拆解是为了学：学它为什么火、怎么讲，借它的选题和信息，**我们的视频要自己写、自己做**。

## 流程

1. **先看拆过没有**：调用 `get_teardown`。已经有报告、参数里也没写「重新拆解」，就不要重拆，直接汇报「已经拆过」和报告的一句话总结，结束。
2. **读材料**，三样都读：
   - `youtube_transcript`：字幕全文，带时间。不要传 `refresh`，有存好的就用存好的。拿不到时工具会说明原因，**不要用任何别的办法绕过**（不找第三方下载站、不换别的工具去拉），这次就只用简介和评论来拆，报告开头写明「没拿到字幕：原因」。
   - `youtube_videos`：完整简介（常有章节时间轴、工具链接、价格）、时长、播放点赞评论数、发布时间。
   - `youtube_comments`：热门评论，读一次就够。
3. 按下面的格式写报告，调用 `save_teardown` 存到这条视频上（`title` 填视频标题）。
4. 汇报：一句话总结，加上最值得借的一点。

## 报告格式

用 Markdown，按这几节写，每节写具体的，不写空话：

- **一句话**：这条视频讲了什么、凭什么火（结合播放速度、发布时间、评论数）。
- **为什么火**：选题戳中了什么情绪或需求、时机、标题和封面的说法。
- **结构时间线**：按时间分段（`0:00–0:15 钩子`、`0:15–1:30 …`），每段一句话写它在干什么、用了什么手法（反转、数字、实测、对比、悬念……）。没有字幕时按简介里的章节写，没有章节就写「不知道」，不要编。
- **开头钩子**：前 15 秒怎么留住人。用你自己的话描述手法，可以引用不超过一句的原话。
- **节奏和画面**：语速、信息密度、多久换一个点；画面看不到，只能从字幕和简介推断的就写明是推断。
- **评论区**：观众在夸什么、争什么、追问什么、不满什么。追问和不满往往就是我们能做得更好的地方。
- **可以借的**：话题本身、值得再讲一遍的信息点（**每条都要在调研时重新查证**，标上原视频只是线索）、结构和手法。
- **不能碰的**：原视频的稿子（不逐句翻译、不改写成我们的稿）、画面和剪辑素材、主持人和角色形象、独家的实测数据和采访内容。
- **我们可以怎么做得不一样**：2–3 个方向，比如换一个人群、补上评论区追问的点、用我们的账号人设和固定角色重讲、做成更短的版本。

## 规矩

- 字幕只用来理解原视频。报告里不要大段贴字幕，引用原话每处不超过一句，并且整份报告引用不超过三处。
- 不确定的写「不确定」，不要替原作者补细节。
- 原视频里的事实和数据只是线索，报告里不要当成已经核实的结论。
