# 技能：现在是怎么运作的

SoloMCN 里「每个环节怎么做」都写在技能里。平台不规定具体做法，只做三件事：

- 把规则放好：每条规则都在一个技能里，用到时才读。
- 让变化看得见：技能的每一次变化都能看对比、能撤回。
- 让经验沉淀下来：实践里踩的坑回到对应的技能。

## 技能是什么

就是标准的 Claude Code 技能：一个文件夹，`SKILL.md` 是入口，开头的 `description` 是简介，正文写步骤；细节放同目录的附录文件，程序放 `scripts/`。Claude Code 自己负责加载：

| 什么时候进上下文 | 内容 |
|---|---|
| 一直在 | 每个技能的名字和简介 |
| 要用这个技能时 | `SKILL.md` 正文 |
| 正文里提到、真用到时 | 附录、做法各环节的文件、程序 |

技能分三类，格式一样，只是用途不同（`SKILL.md` 开头 `metadata.kind` 标着）：

| 类 | 是什么 | 出厂带的 |
|---|---|---|
| 流程（不标） | 一个环节的通用步骤，工作台点按钮时调用 | `curate-topics` `daily-topics` `account-ideas` `teardown-video` `research-topic` `write-script` `precheck-content` `make-video` `revise-video` `review-data` `improve-skills` |
| 做法（`kind: craft`） | 一种内容各环节具体怎么做，按环节分文件（`research.md` `script.md` `video.md` `revise.md`，只写和通用流程不一样的环节） | `explainer-video`（解说视频，默认）、`stage-montage`（原片剪辑：一键换装、舞台混剪） |
| 工具（`kind: tool`） | 几处都会用的程序和它的用法 | `voice-over`（配音）、`transcribe`（语音转文字） |

放哪里的判断：只有一种做法用的，放进那个做法；几种做法都用的，放流程技能或工具技能。某个系列特有的要求（比如某个词怎么念）写在系列设定里，不写进技能。

## 一次运行怎么拿到要用的技能

1. **流程**：工作台调用时消息开头就是技能名（`/make-video 内容 id：…`），直接加载。
2. **做法**：内容卡片上记着这条用哪种做法（`craft`），没有就看系列设定里选的；系列选「自动」时，写脚本时由 Claude 按内容挑一次，存到卡片上，后面的环节照用。平台调用时把它带上（`；做法：stage-montage`），流程技能读那个做法里本环节的文件。
3. **工具**：做法文件里直接写用哪个（「配音按 /voice-over」）。临时需要别的，Claude 按技能简介自己找。

## 每次运行能做什么

所有运行的能力都一样，不按任务拆权限：读写文件、执行命令、上网、加载技能、开子代理，加上 workbench 的 MCP 工具。

- **钥匙和登录**：你在工作台里配过的，每次运行直接放进环境变量，提示里列出名字，比如 `DASHSCOPE_API_KEY`、`IMAGE_API_KEY`、`YOUTUBE_API_KEY`、`YOUTUBE_COOKIES_FILE`、`BILIBILI_COOKIES_FILE`、`SOLOMCN_CLAUDE_TOKEN`。B站、YouTube 的登录导出成 cookie 文件，`yt-dlp --cookies` 直接能用。命令行里再开 Claude Code 时，用 `CLAUDE_CODE_OAUTH_TOKEN=$SOLOMCN_CLAUDE_TOKEN claude -p …`。见 `server/credentials.js`。
- **MCP 工具**只做平台本身的事：读写工作台的数据（内容、调研、脚本、视频、素材），用你账号会话的功能（B站搜索和剪片、发布、带登录的实践浏览器），以及停下来问你一件事。
- **下载默认位置**：Hugging Face、PyTorch 模型和 pip 缓存默认落在 `data/programs/`（`HF_HOME`、`TORCH_HOME`、`PIP_CACHE_DIR`），只对工作台启动的运行生效，你自己的终端不受影响。
- **找文件**只在项目目录和任务给出的位置找，不在整个家目录里大范围搜（会碰到别的 App 的数据，macOS 会弹窗）。

这些都在你自己的电脑上、用你自己的账号运行，请只在你信任的电脑上用。

## 技能改动

技能的每一次变化都是一条「技能改动」，在技能页「技能改动」里，能看逐行对比、能撤回。

| 从哪来 | 谁动手 | 默认 |
|---|---|---|
| 你的想法：总览页、技能页「说一句」，或「＋ 新技能」 | `improve-skills` 在草稿里改 | 先给你看 |
| 运行中改的：自我进化开着时，Claude 在任何运行里遇到坑、找到更好的做法，直接改对应技能 | 那次运行 | 直接生效，可撤回 |
| 出厂更新 | 平台逐个文件三方合并；合不上的交给 `improve-skills` | 没冲突直接生效；有冲突先给你看 |
| 定期整理：自我进化开着、上次整理后又攒了 5 条以上、隔了一周 | `improve-skills` | 直接生效，可撤回 |
| 你自己在技能页改 | 你 | 保存即生效 |

- 「先给你看」的改动先改在草稿里，不影响正在跑和之后的任务，点「通过」才写进在用的技能；草稿期间技能被别处改过，通过时按三方合并。「再改改」接着同一份草稿改。
- 运行中改的：每次运行开跑前给 `.claude/skills` 存一份快照，跑完对比，有变化就记一条（同时在跑的其他运行、你在页面上的修改，不会算进这次运行）。
- 每类来源直接生效还是先给你看，在技能页「哪些改动要先给你看」里改。
- 自我进化总开关在技能页，关掉后运行里不会再改技能。
- 做法和工具可以单独关掉：关掉的挪出 `.claude/skills`，不占 Claude 的上下文。流程技能是各环节的入口，不能关。
- 出厂技能不能删，可以关；自己加的可以删，删了也记成一条改动。

## 东西都在哪

| 位置 | 是什么 |
|---|---|
| `defaults/skills/` | 出厂版本（在代码仓库里） |
| `.claude/skills/` | 在用的技能，你的本地数据，不进 git。在 Claude Code 里直接 `/make-video` 用的也是这份 |
| `data/skills/base/` | 每个技能是基于哪一版出厂版本装的，用来判断「改过没有」和三方合并 |
| `data/skills/changes/` | 每条技能改动前后的文件、草稿 |
| `data/skills/disabled/` | 关掉的技能 |
| `data/programs/` | 实践中装的程序和模型（Ghidra、JDK、whisper 模型……），`programs.json` 记着用途、位置和上次使用时间，「设置 → 实践占用空间」里能看、能删，久没用的自动清理 |
| `data/credentials/` | 从你的登录导出的 cookie 文件，每次运行前重写 |
| `videos/<项目>/` | 每条视频的工程；`videos/lab-<内容 id>/` 是调研动手实践的实验目录 |

## 代码在哪

| 文件 | 管什么 |
|---|---|
| `server/skills.js` | 同步出厂版本、技能改动（草稿、对比、通过、撤回、三方合并）、开关、运行前后的快照 |
| `server/agent.js` | 启动每次运行：同一套工具、提示里加自我进化和凭据说明、`improve-skills` 任务 |
| `server/credentials.js` | 把配过的钥匙和登录整理成环境变量 |
| `server/index.js` | 技能和技能改动的接口、改进技能的排队 |
| `public/app.js` | 技能页、技能改动卡片、总览页的「说一句」 |
