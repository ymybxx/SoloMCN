# 技能编排：流程技能 + 做法技能

## 一、出发点

平台的价值是**替用户维护那些繁琐的规则和数据**，并把每次实践的经验沉淀下来。具体怎么做，交给 Claude 发挥。平台不规定做法，只负责三件事：

- **放好**：每条规则放在该放的地方，用到时才读；
- **看得见**：规则每一次变化，都能看出改了什么、为什么改；
- **长得出来**：实践中踩到的坑，回到对应的规则里。

现在的问题：

| 问题 | 例子 |
|---|---|
| 做法和流程混在一起 | make-video 约 4 万字，换装剪辑、解说视频、解说员全塞在里面；每次出片整篇读进上下文 |
| 同一做法散在四个技能里 | 原片剪辑在调研、写脚本、出片、修改四个技能里各写了一段，加一种风格四处都要改 |
| 用不上的也要背着 | 只做口播解说的用户，每次都带着几千字换装规则 |
| 更新看不出变化 | 出厂说明更新只提示「有新版本」，看不到改了哪几句、为什么 |
| 经验沉淀不下来 | 实践中发现的坑只留在那次对话里，下次还会再踩（调研的「经验本」只覆盖调研） |

## 二、五层边界：每样东西只有一个家

| 层 | 是什么 | 放在哪 | 谁改 | 例子 |
|---|---|---|---|---|
| **平台** | 程序本身 | 代码仓库 `server/`、`public/` | 开发者 | 工作台、调度、MCP 接口 |
| **技能** | 怎么做（文字规则） | `.claude/skills/` | 用户、Claude（进化） | 流程技能、做法技能 |
| **工具箱** | 会被多处用到的程序 | `.claude/toolbox/<工具>/`（程序 + 一页说明） | 出厂、Claude 实践中装 | 配音合成、生图、语音回听（whisper）、B 站下载、反编译工具 |
| **资料** | 你是谁、你有什么 | `data/` | 用户、Claude | 账号、系列、解说员形象、音色库、读音表、素材、作品 |
| **连接** | 账号登录和密钥 | 设置页（`data/secrets.json` 等） | 用户 | Claude 登录、生图 key、通义 key、B 站 / YouTube 登录、模型选择 |

判断规则，一句话一条：

- 写的是「**怎么做**」→ 技能；只有一种做法用的程序，跟着这个做法放在它的目录里（montage 属于原片剪辑）；
- 是一个**程序**，两个以上做法或环节会用 → 工具箱；
- 描述「**你是谁、你有什么**」→ 资料。技能里不写具体账号、具体音色、具体人；
- 是**密码、密钥、登录** → 连接，只在设置页，技能和资料里都不出现。

工具箱里每个工具一页说明：干什么、怎么调用、依赖装在哪（比如 whisper 模型的位置）、已知的坑。Claude 实践中新装的工具（比如调研时装的 ghidra），也登记进来，下次直接用，不用每次重新找。

**经验回到它所属的那一层**：做法的坑 → 做法对应环节；工具或环境的坑（「whisper 模型在 X」「通义要首字母大写才连读」）→ 那个工具的说明；和做法无关的流程问题 → 流程技能。原来调研的「经验本」（`videos/lab-shared/NOTES.md`）拆进这几处后停用。

现在需要搬家的：

| 现在 | 问题 | 搬到 |
|---|---|---|
| `voice-over/voices.json`（音色库） | 用户资料放在技能里 | 资料：`data/voices.json` |
| `voice-over/scripts/` 和 `lab-shared/tools/tongyi-tts.mjs` | 同一个配音程序放了两份 | 工具箱：配音合成 |
| 根目录 `tools/img.mjs` | 共用程序，没有说明 | 工具箱：生图 |
| `lab-shared/tools/`（ghidra、jdk……） | 只有调研知道 | 工具箱（调研装的工具） |
| `lab-shared/NOTES.md` | 经验只在调研里用 | 拆回做法 / 工具 / 流程 |
| 读音（这次的 tulpa） | 没地方记 | 资料：账号或系列的读音表，配音时自动套用 |

技能页分三栏：**做法**、**流程**、**工具箱**。资料在账号、系列、角色页面；连接在设置页。用户只要记住「规则在技能页、东西在资料里、登录在设置」。

## 三、两类技能

**流程技能**（现在这些，保留）：每个环节的通用流程，和做什么内容无关。

> 选题、调研、写脚本、生成视频、修改视频、发布……

每个流程技能只写：读什么、产出什么、怎么登记回平台、怎么汇报。遇到「具体怎么做」，就去读这条内容所用做法的对应一节。

**做法技能**（新增）：一种内容的完整做法，从调研到修改，按环节分开写。

```
.claude/skills/craft-footage/        ← 原片剪辑（一键换装、舞台混剪）
  SKILL.md        做法简介：适合什么内容、需要什么素材、各环节说明在哪
  research.md     调研：去哪找素材、挑什么样的、怎么体检
  script.md       写脚本：剪辑方案怎么写
  video.md        生成视频：montage 工具怎么用、贴合换装、舞台段、审片
  revise.md       修改视频：按意见怎么改切点、转场、调色
  scripts/        montage.mjs、lockfx.swift、pose.swift、array.swift ……
  CHANGES.md      变化记录（每一条：什么时候、谁改的、改了哪个环节、为什么）

.claude/skills/craft-explainer/      ← 解说视频（现在 make-video 里的 HyperFrames 部分 + 解说员）
  SKILL.md / research.md / script.md / video.md / revise.md / scripts/ / CHANGES.md
```

- 某个环节没什么特别的，就不写那个文件，流程技能按通用做法来；
- 以后加新风格（比如「图文轮播」「直播切片」），就新增一个做法目录，不碰别的；
- 文件名固定，是为了让平台能按环节显示、对比和统计。

## 四、怎么串起来

**系列选做法**：系列设置里加一项「做法」（下拉，只列出已启用的），可以选「自动」，由 Claude 按脚本判断。系列里原来的「固定结构」继续是系列自己的风格要求（比如「舞台安利：丝滑换装，副歌加快」），不写做法细节。

**平台在调用时告诉 Claude 读哪一份**，不让它整篇翻找：

```
/make-video 内容 id：xxx；做法：原片剪辑（这一环节的说明：.claude/skills/craft-footage/video.md）
```

这样每个环节只读：流程技能（短）+ 这个做法的这一节。不用这个做法的用户和内容，完全不会读到它。

## 五、开关

技能页每个做法有两个开关：

| 开关 | 默认 | 作用 |
|---|---|---|
| 启用 | 出厂做法都开 | 关掉后不装进 `.claude/skills`，系列里选不到，也不占上下文 |
| 自我进化 | 开 | 开着时，任何环节实践中遇到问题、找到更好的做法，Claude 都可以直接改这个做法对应环节的说明 |

出厂做法和其他技能一样：用户能改；没改过的随出厂更新自动跟上；改过的提示合并。

## 六、自我进化

开着「自我进化」时，每个环节的提示里多一句：

> 这次做的时候，如果遇到了说明里没写到的坑、发现说明有错、或者找到了明显更好的做法，做完后调用 `improve_craft`，改这个做法对应环节的说明。

`improve_craft`（新的 MCP 工具）：

- 参数：做法、环节、改动后的整段内容、一句话原因、出自哪条内容哪次运行；
- 平台先存一份旧版，再写入，并在 CHANGES.md 和技能页「动态」里记一条；
- 规则：**改，不要只往后追加**（相同主题合并、过时的删掉），每个环节文件有字数上限，超了就让 Claude 先整理再改；
- 每条改动都能一键撤回。

这也取代了调研里单独的「经验本」：调研里的经验直接回到对应做法的 research.md。和具体做法无关的通用经验（比如「B 站下载要登录才有 1080P」），回到流程技能里。

## 七、看得见变化

所有版本变化都用同一个对比视图，按行显示增删（左旧右新，或者行内标红标绿）：

- **出厂更新**：每次出厂更新附一句「这次改了什么」（来自 CHANGES.md），点开看逐行对比；没改过的直接换上，改过的看三方：出厂旧版 → 出厂新版、出厂旧版 → 你的版本，再选合并、覆盖或保留；
- **Claude 进化**：动态里每条显示「哪次运行、改了哪个环节、为什么」，点开看对比，不满意就撤回；
- **自己改**：保存时可以选填一句原因，历史版本都能对比、载入。

## 八、技能页

```
技能
├─ 做法                         ← 卡片：解说视频 / 原片剪辑 / ＋ 新做法
│   原片剪辑   [启用 ●] [自我进化 ●]   用在：舞台安利
│     调研 · 写脚本 · 生成视频 · 修改       ← 按环节切换，直接编辑
│     动态：10/11 Claude 在《苏新皓…》出片时改了「生成视频」：被挡的段落改用舞台段（对比 · 撤回）
│           10/10 出厂更新：逐帧认人（对比）
└─ 流程                         ← 选题、调研、写脚本、生成视频……（和现在一样）
```

「＋ 新做法」：用一句话描述要做的东西，Claude 起草各环节说明；也可以在某次运行结束后点「存成新做法」，把这次的做法提炼出来。

## 九、迁移

| 现在在哪 | 搬到哪 |
|---|---|
| make-video「原片剪辑」一节 + scripts/montage 等 | craft-footage/video.md + scripts/ |
| research-topic「B 站素材」「换装素材标准」 | craft-footage/research.md |
| write-script「剪辑方案」格式 | craft-footage/script.md |
| revise-video 原片修改部分 | craft-footage/revise.md |
| make-video HyperFrames 制作、画质、解说员、配乐、审片 | craft-explainer/video.md（+ presenter、synth-bgm 等脚本） |
| docs/stage-edit-plan.md 的剪辑原则 | craft-footage/video.md 开头 |
| 服务端写死的 `.claude/skills/make-video/scripts/montage.mjs` 路径（素材体检） | 指到 craft-footage/scripts |

| revise-video「改一处就整条重渲染」 | 改个读音要 10 分钟 | 各做法的 revise.md 写明：时长不变的局部修改（换一句配音、改一条字幕、改一刀）只重做受影响的那几秒再拼回原片，解说员也只叠这一段 |

流程技能瘦身后，make-video 预计从 4 万字降到 5 千字以内。已有内容卡片和视频都不用动：老系列没选做法时，按「自动」处理，效果和现在一样。

## 十、做完怎么验收

- 苏新皓换装这条：用新结构重新「生成视频」，切点、成片和第十九版一致；
- 一条普通解说视频：生成流程不读到任何原片剪辑内容（看运行记录里读了哪些文件）；
- 关掉「原片剪辑」：技能列表、系列下拉里都消失，`.claude/skills` 里没有这个目录；
- 打开自我进化，跑一次修改：动态里出现一条带原因的改动，对比能看、能撤回；
- 出厂更新一个做法：技能页能看到这次改了什么和逐行对比。
